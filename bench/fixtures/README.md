# bench/fixtures

Canned inputs so the whole `templates/govern/test/test-bench-*.sh` suite runs with zero spawns and
zero spend.

## Live A/B harness fixtures

Canned `claude -p --output-format stream-json` streams for `bench/run.sh --dry-run`.

| File | Stands in for |
|---|---|
| `vanilla-session.jsonl` | the one long session the `vanilla` (without shiploop) arm runs over a whole backlog |
| `vanilla-fresh-session.jsonl` | one fresh-context, per-ticket session for the private `vanilla-fresh` arm |
| `shiploop-session.jsonl` | the one advisor session the `shiploop` (with shiploop) arm runs over the same backlog, forwarding two worker subagents' turns and carrying a `subagent_stats` block on its `result` event |
| `partial-no-result.jsonl` | a session hard-killed before it emitted a `result` event |

The numbers in these are synthetic and arithmetically convenient. They carry no claim about real
runs and nothing published may be computed from them.

## Golden results fixtures

| File | What it is |
|---|---|
| `golden-results.jsonl` | a `results.jsonl` for one backlog, four shiploop sessions and one vanilla session, locking the arithmetic `bench/rollup.mjs`'s three metric cuts assert against |
| `selection-results.jsonl` | five backlogs exercising the selection ranking: three comparable with different cost deltas, one whose vanilla arm failed to clear, one capped |

Both are static, hand-derived `results.jsonl` rows, not the output of a run. Every dollar figure in
them is priced from the row's own token counts at published rates (`test-bench-selection.sh`'s own
case 7 asserts this), so no number in either file was chosen independently of its tokens. The
`vanilla` rows in both files are a fixed synthetic input standing in for a real without-shiploop
session, not a measurement of one; the `shiploop` rows likewise stand in for real with-shiploop
sessions. Neither file is regenerated by a script — edit them by hand and re-derive the arithmetic
below if the shape of a cut ever changes.

### golden-results.jsonl derivation

| Ticket | Model | Turn contexts | input | cache write | cache read | output | total | cost |
|---|---|---|---|---|---|---|---|---|
| 101 | opus | 50k .. 400k, 8 turns | 10,000 | 47,000 | 1,743,000 | 40,000 | 1,840,000 | $2.3915 |
| 102 | opus | 50k .. 300k, 6 turns | 10,000 | 37,000 | 1,003,000 | 30,000 | 1,080,000 | $1.6715 |
| 103 | opus | 50k .. 250k, 5 turns | 10,000 | 32,000 | 708,000 | 20,000 | 770,000 | $1.2240 |
| 104 | sonnet | 300k, 500k, 700k | 10,000 | 22,000 | 1,468,000 | 25,000 | 1,525,000 | $0.6516 |

Shiploop arm: **5,215,000 tokens, $5.9386.** Each ticket's `total_cost_usd` is set to exactly what
the published rates give, so a rate-table regression shows up as a drift rather than as nothing.

The vanilla row is a single fixed session over the same four tickets: 40,000 input, 115,000 output,
11,522,000 cache read, 102,000 cache creation (11,779,000 total), $8.5006. It is not derived from
the shiploop row by any formula; it is chosen so the resulting cuts (30.1% lower cost, 55.7% fewer
all-in tokens, 14.0% MORE billable tokens) exercise every branch `bench/rollup.mjs` prints,
including the negative billable-tokens case (a run of fresh per-ticket sessions can write more cache
than one long session does) and the "which cut is larger" headline selection.

Two properties this fixture exists to lock:

- **Ticket 101 in isolation saves exactly 0%** against an equivalent lone-ticket vanilla run — the
  fixture does not assert this directly, but the derivation is kept here so a future edit can
  re-check it by hand.
- **Summing the stream is a trap.** Every assistant event in a real stream reports a truncated
  `output_tokens` snapshot; `golden-results.jsonl`'s rows carry the correct `result`-event totals
  directly so `bench/rollup.mjs`'s test never depends on stream-summing being right.

### selection-results.jsonl derivation

Five backlogs, each a (vanilla, shiploop) cost pair chosen for its own carry multiplier so the
ranking has a real spread to sort:

| Backlog | vanilla | shiploop | cost cut | note |
|---|---|---|---|---|
| `bl-a` | $47.97 | $20.57 | 57.1% | both arms clear |
| `bl-b` | $30.76 | $18.00 | 41.5% | both arms clear |
| `bl-c` | $17.63 | $15.43 | 12.5% | both arms clear |
| `bl-d` | $34.15 | $17.14 | 49.8% on paper | vanilla cleared only 5 of 8 tickets — dropped |
| `bl-e` | n/a | $0.00 | n/a | the run hit `BENCH_MAX_USD`; shiploop recorded `capped` — dropped |
